# 版本与下游续训 {#versions-and-downstream-resume}

实验详情中的版本记录用于核对一次运行实际使用的源码、配置、输入和模型身份。相同内容可以关联多个实验，版本 ID 表示内容身份，不表示性能排名。

## 查看版本 {#inspect-versions}

打开实验详情的版本区域，查看记录状态、各类内容版本及关联运行，并可下载版本摘要 JSON。只有有权访问对应实验的账户才能读取记录；公开响应过滤本机路径、执行命令与内部错误。

新运行会捕获依赖并封存成功模型。封存或完整性检查失败的模型不能作为已验证模型推理；`not_recorded` 表示旧实验没有版本记录，不代表模型已完成新版本验证。参见[版本 API](../api/versions)。

## 重跑与续训的区别 {#rerun-versus-resume}

“重跑”把配置复制到新实验草稿，允许修改参数并重新训练，不是恢复原训练进程。

当前“下游续训”专用于**失败的 SVM 实验**：源实验必须保存通过完整性校验的下游嵌入恢复包。它创建一个新实验，复用已保存表征，只重新拟合下游 SVM。它不提供任意模型的 epoch 级断点恢复，也不自动恢复服务重启时中断的训练。

## 使用下游 SVM 恢复 {#resume-a-downstream-svm}

1. 在失败实验中检查是否出现恢复入口及可用恢复包。
2. 调整 SVM 收敛、正则化或受支持的缩放、降维、调参设置。
3. 保留 SVM 分类器和原校准模式；不能更换上游编码、数据集或训练表征。
4. 预检通过后提交新实验，原失败记录保持可追溯。

允许覆盖的字段以[实验 API](../api/experiments)为准；创建消耗正常实验配额。CLI 对应参数为 `--resume_embedding_bundle`，需要有效的恢复包，不能传入任意模型目录。
